# UI 방향 탐색

**선택 완료: 1번(01-quick-confirm.png).** 사용자 선택을 기준으로 Android 네이티브 UI 구현을 진행 중이다. 나머지 이미지는 탐색 기록이다.

가칭: 바로입력. 화면 논리 크기: 390 × 844. 생성 이미지는 시각 콘셉트이며 구현 또는 접근성 검증 결과가 아니다.

## 저장된 결과 — 대화 표시 순서

1. [첫 번째 시안](01-quick-confirm.png)
2. [두 번째 시안](02-large-type.png)
3. [세 번째 시안](03-line-selection.png)

생성 도구: 기본 제공 ImageGen. 별도 API 키·외부 OCR 서버 사용 없음. 이미지에 보이는 인식 결과는 합성 예시다.

## 생성 지시 요약

공통: 390×844 논리 화면의 한국어 Android UI 한 장. 휴대폰 외곽·상태바 없이 외부 앱의 제품번호 입력칸과 아래 IME를 표시. 실제 카메라 라벨 같은 원본 이미지, 큰 글자, 명확한 한 가지 주요 행동. 예시 번호 0012 3456 7890. 불필요한 카드·통계·정확도 수치 제외.

- 첫 번째: 따뜻한 흰색, 청록 #087F72, 원본과 큰 인식 결과, 공백 제거, 수정·다시 스캔·입력, 키보드 전환.
- 두 번째: 남색 #111C2E, 노랑 #FFD86B, 큰 숫자 중심, 원본 스트립, 번호 듣기, 수정, 이 번호 입력, 키보드 전환.
- 세 번째: 흰색, 파랑 #2459D3, 제품 라벨의 세 줄에서 한 항목 선택, 얇은 구분선, 선택한 항목 입력, 다시 스캔, 키보드 전환.

## 시각 검토 메모

모든 이미지에서 주요 문구·숫자와 키보드 전환을 육안 확인했다. 첫 시안은 요청보다 외부 폼이 많은 공간을 차지하므로 상세 설계에서 축소한다. 두 번째는 확대 글꼴에서 버튼이 밀리지 않도록 스크롤/높이 조절이 필요하다. 세 번째는 항목 선택 화면이며, 삽입 전 수정 경로를 상세 화면에 추가해야 한다. 작은 보조 동작의 터치 영역, 정확한 대비, TalkBack 동작은 이미지로 검증할 수 없다. 생성된 그라데이션·그림자는 구현 토큰에서 제거할 수 있다.

## 빠른 확인

밝은 바탕과 청록 강조. 다른 앱 아래의 키보드 패널 안에서 원본 영역과 인식 결과를 한눈에 확인하는 균형형 구성. 한 번의 스캔과 삽입에 집중.

## 큰 글씨 집중

짙은 남색과 따뜻한 황색. 원본보다 읽은 번호를 크게 배치하고 큰 동작 버튼을 사용. 정지·확인 중심이며 작은 툴바와 숨은 제스처를 줄임.

## 한 줄씩 선택

흰색과 코발트 강조. 한 화면에서 읽힌 여러 줄 중 필요한 항목 하나를 명시적으로 선택한 뒤 삽입. 반복 입력의 기반이 되지만 첫 버전에서 배치 자동 입력은 제외.

최종 방향은 대화에 표시된 세 이미지의 순서로 선택한다. 방향 선택 이후 화면별 상세 설계와 인터랙션 시제품을 진행한다. 이미지의 문구나 치수에 차이가 있으면 docs/ux-spec.md의 기능·접근성 요구를 우선 적용한다.
