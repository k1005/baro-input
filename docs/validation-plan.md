# 기술 검증과 구현 계획

## 기술 구성 후보

- Kotlin 네이티브 Android 앱 + InputMethodService.
- CameraX 또는 Camera2: IME 서비스의 카메라 수명주기를 먼저 검증한 뒤 선정.
- ML Kit Text Recognition: 한국어·라틴 모델 번들 후보. 앱 설치 후 네트워크 없는 상태에서 테스트.
- InputConnection.commitText: 사용자가 확정한 결과만 전달. 현재 편집 세션과 연결이 달라졌으면 삽입 취소.
- 본체 앱의 권한·설정 화면과 IME UI를 분리. IME가 Activity라고 가정하지 않음.

## 먼저 통과할 기술 관문

1. IME 패널에 카메라를 표시하고 화면이 보이는 동안만 접근 가능한지.
2. 카메라 권한 최초 허용·거절·회수 후 복구 가능한지.
3. 촬영 → 확인 → 삽입 동안 원래 입력 연결이 유지되는지.
4. 다른 앱으로 전환·회전·화면 잠금·프로세스 재시작 후 카메라/임시 데이터가 남지 않는지.
5. 다른 앱이 카메라를 점유한 경우 정상 복구하는지.
6. 긴 번호·앞자리 0·한글·공백·줄바꿈·숫자 제한 필드에서 결과가 보존되는지.

IME 내 카메라 호환성 문제가 크면 별도 촬영 Activity + 사용자가 돌아온 뒤 명시적 결과 선택을 대안으로 검토한다. 이전 InputConnection을 저장해 나중에 무조건 재사용하지 않는다.

## 실기기 / 대상 앱

출시 시점 지원 OS의 최신·직전 버전, 삼성과 비삼성 각각, 중급 성능 기기 포함. 메모, Chrome 일반 폼, 메시지 초안, 업무용 입력 폼을 우선 확인한다. 보안 키패드·IME 차단 앱은 별도 호환성 목록에 기록한다. 실제 사용자의 데이터 대신 합성 샘플 사용.

## 사용자 비교 시험

초기 6–8명으로 문제 발견용 테스트. 큰 글씨 사용·TalkBack 사용·손 조작이 불편한 참여자 포함. 경쟁 제품과 우리 시제품의 사용 순서를 교차 배치한다.

과제: 최초 설정, 12자리 숫자, 앞자리 0, 영문 제품번호, 한글 한 줄, 흐린 인쇄물 수정, 권한 거절에서 복구, 기존 키보드 복귀.

기록: 성공/실패, 최종 일치 여부, 완료 시간, 탭 횟수, 오류 수정 횟수, 도움 요청, 조준 피로, 개인정보 설명 이해도. 경쟁 앱에 없는 기능은 비교 성공으로 계산하지 않고 별도 보고.

## 단계

1. 기획 + 독립적인 UI 방향 3개 → 시각 방향 선택.
2. 선택안의 화면 상세 설계 + IME/카메라 기술 시제품.
3. 실제 OCR·결과 수정·삽입을 묶은 내부 APK.
4. 접근성·기기 호환성·사용성 비교 및 개선.
5. Play 등록용 설명·개인정보처리방침·데이터 보안 응답·테스트 요건을 당시 최신 정책으로 확인.

현재 단계에서 스토어 출시, 계정 생성, 유료 서비스 연결은 실행하지 않는다. 일정 추정은 카메라/IME 기술 관문 통과 후 작성한다.
