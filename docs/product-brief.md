# 제품 기획 v0.1

## 핵심 약속

“보이는 글자를, 확인하고 바로 입력.”

우선 대상은 제품번호·배송번호·인쇄된 연락처·짧은 문장을 옮겨 입력하는 Android 사용자다. 큰 글씨, 한 손 조작, 화면 읽기 도구를 사용하는 사람도 핵심 과업을 수행할 수 있도록 설계한다. 시각장애·운동장애 접근성을 이미 검증했다는 주장은 하지 않는다.

## 해결할 문제

1. 카메라 앱에서 인식하고 복사한 뒤 원래 앱을 다시 찾는 과정이 길다.
2. 긴 번호는 한 글자 오류를 발견하거나 고치기 어렵다.
3. 기존 스캐너 키보드는 설정과 부가 기능이 많아 처음 쓰는 사람이 핵심 기능을 찾기 어려울 수 있다. 이는 사용자 테스트 전 가설이다.

## 첫 버전의 범위

| 우선순위 | 기능 | 완료 조건 |
|---|---|---|
| P0 | 입력기 활성화 안내 | 실제 활성 상태를 읽어 단계 표시, 연습 입력 가능 |
| P0 | 스캔 | 현재 모드와 촬영 상태 표시, 정지 화면에서 영역 선택 가능 |
| P0 | 숫자 / 텍스트 모드 | 숫자 필드에서는 숫자 모드를 제안하되 전환 가능 |
| P0 | 결과 확인 | 원본 부분 이미지와 결과를 함께 표시 |
| P0 | 수정 | 커서 이동, 삭제, 숫자 키패드, 다시 스캔 제공 |
| P0 | 삽입 | 사용자가 버튼을 누를 때만 현재 연결에 문자열 전달 |
| P0 | 키보드 전환 | 모든 주요 상태에서 시스템 입력기 선택 접근 가능 |
| P0 | 오류 복구 | 권한 거절, 초점 불량, 결과 없음, 연결 해제, 카메라 사용 중 처리 |
| P0 | 접근성 | TalkBack 레이블·순서·포커스·상태 알림 실기기 확인 |
| 이후 | 연속 스캔 / 최근 항목 | 단일 입력의 안전성과 속도 검증 후 추가 |

일반 한글 자판 전체 제작, QR/NFC, 로그인, 자동 전송, 클라우드 OCR, 광고, 구독은 첫 검증 범위에서 제외한다. 텍스트 수정은 스캔 영역 재선택·삭제·공백/줄바꿈 조정 및 삽입 후 기존 키보드에서 편집을 지원한다. IME 안에서 다른 IME를 다시 열 수 있다고 가정하지 않는다.

## 기본 데이터 정책 — 설계 의도

- 카메라는 사용자가 입력기를 사용하고 스캔을 시작했을 때만 사용한다. 화면을 숨기거나 입력을 종료하면 해제한다.
- 사진을 갤러리에 자동 저장하지 않는다. 공유 기능과 원격 분석 SDK는 초기 범위에 넣지 않는다.
- 취소·입력 종료 시 임시 결과를 지운다. 앱 전환으로 입력 연결이 바뀌면 자동 삽입하지 않는다.
- 비밀번호 필드에서는 카메라 입력을 비활성화한다. 사용자가 다른 일반 입력칸으로 이동하도록 안내한다.
- “입력 내용을 전혀 보지 않는다”라는 문구는 사용하지 않는다. 입력기는 OS 경고 대상임을 쉬운 말로 설명하고 실제 수집 동작과 일치시킨다.

## 비교 평가 목표

동일 디바이스·대상 앱·인쇄 샘플로 Scanner Keyboard와 비교한다. 지원되지 않는 한글 항목은 별도 표시하고 공통 지원 영문·숫자에서 먼저 비교한다.

- 활성화 이후 12자리 숫자 입력의 중앙 완료 시간: 경쟁 앱 대비 25% 이상 단축 목표.
- 수정까지 포함한 최종 문자열 완전 일치율: 기준 앱 이상. 긴 번호는 글자 정확도보다 완전 일치율을 우선.
- 최초 설정: 도움 없이 2분 이내 연습 입력을 마치는 비율 80% 이상 목표.
- 시각 상태만으로 과업이 진행되지 않도록 TalkBack으로 설정·스캔·수정·삽입·취소 테스트.

샘플이 적은 내부 시험은 방향 판단용이며 시장 성능 주장으로 사용하지 않는다.
